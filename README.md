> ### 🔮 _What is NecroCode?_
>
> A cinematic **3D horror cyber-gothic exorcist studio** wrapped around a
> **real static-analysis engine**. Paste or upload JavaScript/TypeScript for
> deterministic repairs, or any of **29 supported runtimes** for live AI repair
> and sandbox execution. Add an optional **ritual directive**, then watch a WebGL
> ritual graph react as the server streams every corruption it finds, every safe
> counter-sigil it applies, and the purified artifact.

</div>

```
   ᛟ Corrupted Code  ─▶  ᚨ Spectral Scanner  ─▶  ᚱ Kiro Exorcism Reasoning  ─▶  ᛉ Purified Output
```

No fake progress. The scanner reads the actual snippet, the fixes are applied by
a deterministic engine, and the result is streamed over **Server-Sent Events**.
Bring your own Gemini, Groq, or OpenRouter key and the route can add a live model
rewrite; if every provider fails, the deterministic safety net still completes
the rite. The 3D layer is synchronized 1:1 with those real events. The horror is
the costume; the analysis is real.

### ☁️ Zero Setup · 🔒 Private by Default · 📱 Responsive

No `.env`, database, texture, or 3D model is required, and the deterministic
safety net needs no network call. The optional BYOK keys are stored only in your
browser and sent only to this app's own SSE route. **JavaScript sandbox runs stay
in the browser.** TypeScript and every other runtime are executed by the public
Paiza.IO guest runner, so that code leaves this app and is sent to Paiza.IO; the
UI warns you before the first remote run. The only bundled audio asset is the
local horror BGM; SFX are synthesized.

## 🧪 Multi-Language Sandbox

The runtime selector beside the artifact filename chooses how the purified code
is executed. The choice is independent from the static-analyzer language: the
builtin scanner only understands JavaScript / TypeScript / TSX, while the live
engine and the sandbox can handle the full runner set.

| Execution | Runtimes |
| :--- | :--- |
| 🔒 **Local Web Worker** | JavaScript — 2-second kill switch, sealed network globals, stdout/return capture |
| ☁️ **Remote Paiza.IO runner** | TypeScript, TSX, Python 3, Java, C, C++, C#, Go, Rust, Ruby, PHP, Kotlin, Swift, Scala, Haskell, Elixir, F#, D, Perl, R, Bash, SQL (MySQL), Scheme, Common Lisp, Visual Basic, Objective-C, CoffeeScript, COBOL |

The remote path goes through `POST /api/run`, which accepts only the curated
language allowlist, caps source at **24,000 chars**, polls for up to **20 seconds**
server-side, and returns normalized stdout, stderr, build output, exit code,
duration, and memory. The browser adds a **25-second** deadline and labels the
panel `REMOTE`. TypeScript is compiled remotely; TSX / JSX components may still
need a bundler or a plain TS reproduction. Java expects a public `Main` class.

> **Privacy:** remote code leaves your browser and is sent to Paiza.IO. Do not
> paste credentials, tokens, or private source. The public guest runner is
> rate-limited and intended for demos. To use a registered key or a compatible
> self-hosted endpoint, set `PAIZA_API_BASE` and `PAIZA_API_KEY` in the server
> environment; neither value is ever exposed to the client.

### 🔁 Runtime Flow

| # | Step |
| :---: | --- |
| 1️⃣ | User pastes/uploads a **JS/TS artifact** for deterministic scanning, or selects another runtime for live repair + sandbox execution; optionally adds a **RITUAL DIRECTIVE**, and clicks **EXORCISE CODE**. |
| 2️⃣ | `lib/useAgentStream.ts` opens a **POST** `fetch` stream to `/api/agent/stream` with `{ code, directive, language }` and any `x-necro-*-key` sigil headers, then parses SSE frames. |
| 3️⃣ | For JS/TS/TSX, the route calls `exorciseCode()` from `lib/analyzer.ts` first (masking, detection, safe fixes). For other languages it emits an honest pass-through because the builtin rules are JS/TS-only. If sigils exist, it tries Gemini → Groq → OpenRouter with an 8-second timeout each, re-analyzes JS/TS output, and otherwise keeps the deterministic result. |
| 4️⃣ | Each event advances progress, flips a 3D seal `pending → active → done/error`, moves the aura, appends a terminal line, and fires an optional Web Audio blip. |
| 5️⃣ | The final event carries `summary`, `engine`, and `finalCode`; the terminal can copy/download the **full** artifact, export the autopsy, run it in the local JS worker or the remote 28-runtime proxy, and the finished run is saved to the last-10 history drawer. |

## 🔬 Exorcism Rules

| Rule | Severity | Auto-fix |
| --- | :---: | --- |
| Loose equality `==` / `!=` (skips `== null`) | warning | → `===` / `!==` |
| Legacy `var` | info | → `let` |
| `debugger;` | warning | removed |
| `eval(...)` | critical | reported only |
| `parseInt(x)` without radix | warning | → `parseInt(x, 10)` |
| `i <= array.length` off-by-one | critical | → `<` |
| Infinite `while (true)` / `while (1)` | critical | → bounded 1000-iteration `for` loop |
| Assignment inside `if (x = y)` | critical | → `===` |
| Empty `catch {}` | warning | logs the error |
| `throw "string"` | warning | → `throw new Error(...)` |
| Hardcoded API key/secret/token | critical | secret blanked |
| `.innerHTML =` | warning | → `.textContent =` |
| `document.write(...)` | critical | reported only |
| `with (...)` | critical | reported only |
| Blocking `alert(...)` | info | reported only |
| `NaN` comparison | warning | → `Number.isNaN(...)` |
| `setInterval` without `clearInterval` | warning | reported only |
| `TODO` / `FIXME` / `HACK` | info | reported only |
| `console.log/debug/info` residue | info | standalone lines commented |
| Unclosed `{` code block | critical | sealed at end of snippet |
| Unterminated string / unclosed `(` or `[` | critical | reported only |

Unsafe findings are **reported but never guessed at** — the engine only rewrites
when the intent is unambiguous.

When BYOK sigils are configured, the deterministic scan runs first and its
findings are passed to the live model as context. A successful live rewrite
becomes the purified artifact and is re-analyzed for residual findings; any
provider failure leaves the deterministic result untouched. The static rules
above remain the always-available safety floor.

## ⚡ Quick Start

> **📦 Prerequisites:** Node.js **18.18+** (20 or 22 recommended) and npm.

```bash
# 1️⃣  Clone the repository
git clone https://github.com/Fatimahnoman/Necro-Code.git
cd Necro-Code

# 2️⃣  Install dependencies
npm install

# 3️⃣  Start the dev server
npm run dev
#     → open http://localhost:3000  🚀

# 4️⃣  Production build (optional)
npm run build && npm start
```

No `.env` or database is required. The crypt runs on deterministic analysis and
procedural WebGL by default; optional Gemini / Groq / OpenRouter keys can be
added in the browser through **API SIGILS** and are never committed. The public
Paiza.IO guest runner powers non-JavaScript sandbox runs with zero setup; set
`PAIZA_API_BASE` / `PAIZA_API_KEY` only if you have a registered or self-hosted
runner. 🎉

## 🧪 How to Test the Running App

> **Start here after `npm run dev`.** The deterministic path reproduces exactly.
> Live-provider output varies by key, account, model, and network; the fallback
> path is deterministic.

### 1. Verify the studio loads

1. Open **http://localhost:3000**.
2. Confirm the header reads **NECROCODE // AI CODE EXORCIST** and the live pills
   show a phase + `SSE LIVE` + a 3D aura.
3. Confirm the header also shows **API SIGILS**, **HISTORY**, and
   `BUILTIN SAFETY NET` while no keys are configured.
4. Confirm the center **3D Ritual Graph** renders a central skull polyhedron and
   four seals: **Corrupted Code**, **Spectral Scanner**,
   **Kiro Exorcism Reasoning**, **Purified Output**.
5. Drag inside the graph to orbit it. Click a seal — an X-Ray HUD appears with
   the active engine, stage execution time in ms, bug severity breakdown, and
   stage status. Click empty graph space to clear it.
6. Toggle **HORROR BGM**, **3D AUDIO FX**, CRT, and fog in the header. BGM
   starts at `0.22` automatically when allowed, otherwise on the first page
   interaction, and surges to `0.85` during an active exorcism. The two audio
   switches are fully independent.

### 2. Run the default cursed artifact

1. Click **EXORCISE CODE** in the left spellbook.
2. Watch the sequence:
   - **Corrupted Code** turns green.
   - **Spectral Scanner** turns **crimson** with a bug-count badge; the central
     relic heartbeat and aura become crimson.
   - **Kiro Exorcism Reasoning** activates, then the scanner clears.
   - **Purified Output** transcribes code and all seals + aura become **neon green**.
3. The Grimoire terminal streams real logs and the purified code.
4. Expected default summary: **10 cursed · 10 silenced · 0 residual**.
5. Open the **SPECTRAL DIFF** tab in the Grimoire panel. The line-by-line view marks
   every removed original line in crimson `-` and every purified replacement in
   emerald `+`, with old/new line numbers.
6. Click **COPY PURIFIED CODE**; the button switches to **Sigil copied**.
7. Click **REPORT** to download `necrocode-exorcism-report.md` with the
   timestamp, active engine, full findings, applied counter-sigils, and both
   code blocks.
8. Use the download icon in the terminal header to save `purified-artifact.ts`.
9. Click **Banish ritual** to reset all seals, logs, and the aura.

### 3. Optional live directive + BYOK engine

1. Click **API SIGILS**. The modal opens on `BUILTIN SAFETY NET` and explains
   that no key is configured.
2. Paste at least one key: **Gemini**, **Groq / Grok**, or **OpenRouter**. The
   Groq / Grok slot currently calls the Groq OpenAI-compatible endpoint with
   `llama-3.3-70b-versatile`. The modal switches to `LIVE AI ENGINE`; click
   **Seal sigils**. The header badge changes to `LIVE AI ENGINE`. Keys are
   stored in `localStorage["necrocode.api-sigils.v1"]` and sent only as
   `x-necro-gemini-key`, `x-necro-groq-key`, or `x-necro-openrouter-key`.
3. Type a **RITUAL DIRECTIVE** above the editor, for example
   `Convert to strict TypeScript and keep the console output`, then click
   **EXORCISE CODE**.
4. The terminal logs the directive. If a provider returns usable code, the
   terminal shows the live rewrite note and the final engine pill names the
   provider (Gemini, Groq, or OpenRouter). The live output is re-analyzed for
   residual findings.
5. If the key is invalid, the account is blocked, the request exceeds 8 seconds,
   or the reply is not usable code, the stream warns and falls back to the
   builtin `Heuristic` engine. The header returns to `BUILTIN SAFETY NET` after
   that completed fallback run.
6. Reopen **API SIGILS** and click **Clear all** to delete every key. Confirm
   `localStorage` no longer contains `necrocode.api-sigils.v1`, and confirm no
   key ever appears in the terminal, exported report, or history drawer.

> The repository has no automated test suite. A real provider success requires
> a valid key; without one, the dummy-key fallback path above is the
> reproducible check.

### 4. Test the multi-language sandbox and grimoire history

1. Keep the default **JavaScript** runtime and run the normal ritual. After
   completion, click **TEST SANDBOX** beside **COPY PURIFIED CODE**. The panel
   appears with `RUNNING`, then `COMPLETE` and a `LOCAL` badge. Captured
   `console.log` / `info` / `warn` / `error` / `debug` lines and the final return
   value are shown.
2. Run a snippet that never terminates, or a blocking loop, and confirm the panel
   reports `TIMEOUT` after roughly 2 seconds and the worker is terminated.
3. Change the runtime selector beside the filename to **Python 3**, paste a
   snippet such as the one below, click **EXORCISE CODE**, then **TEST SANDBOX**.
   The terminal should warn that the builtin scanner is JS/TS-only, show the
   pass-through line, and the sandbox panel should show a `REMOTE` badge plus the
   Python stdout, exit code, and `Python 3 run complete`.

   ```python
   def summon(name):
       total = 0
       for value in range(1, 4):
           total += value
       print("summoned", name, total)

   summon("necro")
   ```

4. Repeat with a compiled runtime such as **Java**, **C++**, or **Go** and confirm
   compiler errors appear in the panel with an `ERROR` status, while a valid
   program returns `COMPLETE` and its stdout. Java expects a public `Main` class.
   TypeScript is compiled remotely; TSX / JSX components may need a bundler or a
   plain TS reproduction.
5. Remote runs leave the browser and go to Paiza.IO. Do not paste secrets. The
   public guest runner is rate-limited; a transient failure is shown as sandbox
   output rather than crashing the studio.
6. Open **HISTORY** in the header. The slide-over drawer keeps the **last 10**
   completed runs under `localStorage["necrocode.grimoire-history.v1"]`. Each
   entry shows its timestamp, engine, first code line, directive marker, and
   `cursed / fixed / residual` counts. The selected runtime is restored too.
7. Change the editor, then click a history entry. The drawer closes and restores
   the original code, ritual directive, filename, runtime, findings, applied
   fixes, engine, summary, and slimmed terminal logs. The completed result and
   Spectral Diff are available immediately without re-running.
8. Open **HISTORY** again and use **Clear all** to erase the drawer.

### 5. Test the unsafe / residual paths

| Preset | Expected result | Aura |
| --- | --- | --- |
| **Infinite Loop** (default) | 10 detected · 10 fixed · 0 unresolved | Neon green |
| **Memory Leak** | 2 detected · 1 fixed · 1 unresolved (`setInterval` without `clearInterval`) | Crimson |
| **Syntax Corruption** | 3 detected · 0 fixed · 3 unresolved (unclosed brackets/string) | Crimson |

For **Memory Leak** and **Syntax Corruption**, the Spectral Scanner stays
`error`/crimson after completion, and the report shows `RESIDUAL`.

### 6. Test the real SSE API directly (optional)

In PowerShell:

```powershell
$body = @{
  code = "let x = 1;`nif (x = 2) { console.log(x); }"
  directive = "Keep the console output and convert to strict TypeScript."
} | ConvertTo-Json -Compress

Set-Content -Path "$env:TEMP\necrocode.json" -Value $body -Encoding utf8

curl.exe -sN -X POST "http://localhost:3000/api/agent/stream" `
  -H "Content-Type: application/json" `
  -H "Accept: text/event-stream" `
  --data-binary "@$env:TEMP\necrocode.json"
```

You should receive `event: agent` frames with real `stage`, `nodeStatus`, `bug`,
`engine`, and `summary` fields. The last frame also carries `finalCode`,
`originalCode`, `findings`, and `appliedFixes` for the diff and autopsy report.
The last frame's `progress` is `100`.

To exercise the live path, add one or more header flags to the same request:

```powershell
  -H "x-necro-gemini-key: YOUR_KEY"
  -H "x-necro-groq-key: YOUR_KEY"
  -H "x-necro-openrouter-key: YOUR_KEY"
```

Keys travel only as request headers, never in the JSON body or SSE payloads. With
a valid key, the final frame's `engine.name` names the provider; with an invalid
key, it falls back to `Heuristic` and logs a warning.

### 7. Verify the production build

```bash
npm run build
npm start
```

The build must finish with **zero TypeScript/ESLint errors**. Open
`http://localhost:3000` again and repeat the default run.

## 🎮 How to Use

| Action | What happens |
| --- | --- |
| 📜 **Pick a cursed artifact** | Loads a real buggy JS/TS sample into the editor. |
| 📤 **Upload** | Reads a local artifact into the editor; the runtime is detected from the extension when supported. |
| 🐙 **GitHub** | Opens a URL field. Paste a public `github.com/<owner>/<repo>/blob/<branch>/<path>` (or `raw.githubusercontent.com`) link and click **Fetch**; the file, its repo path, and its runtime load into the editor. Files over 24,000 chars, binary files, and private repos are rejected. |
| 🔀 **Runtime selector** | Chooses the sandbox runtime next to the filename: JavaScript stays local; the other 28 runtimes use the remote Paiza.IO proxy. |
| ✍️ **Edit the artifact** | Paste your own snippet; the scanner reads exactly what is in the editor. |
| 🪄 **RITUAL DIRECTIVE** | Optional instruction passed with the code to the live model (for example, convert to strict TypeScript). |
| 🔮 **API SIGILS** | Optional BYOK modal for Gemini, Groq / Grok, and OpenRouter keys; stored in this browser only. |
| 🩸 **EXORCISE CODE** | Opens the SSE ritual: binding → scanning → reasoning → optional live rewrite → purified output. Fires the `DHUM!` slam when **3D AUDIO FX** is on. |
| 🎬 **AUTO DEMO** | Loads the `async-memory-leak` artifact with a demo directive, runs the ritual, then opens **SPECTRAL DIFF** and runs the sandbox. |
| ⏱️ **Timeline** | After a run completes, the `DORMANT · SCANNING · EXORCISING · PURIFIED` buttons under the graph select each stage's seal for inspection. |
| ✅ **GEN TEST** | Builds a smoke test in the runtime's own language: JS/TS assert that each top-level function still exists, Python appends `assert callable(...)`, and every other runtime runs unchanged. Shows `PASS` / `FAIL`, or `PASS (Runtime Smoke Check)` when only the exit code (0) is checked. |
| 🧭 **Runtime pre-flight** | Before **TEST SANDBOX** or **GEN TEST**, a signature check compares the code with the selected runtime. A clear mismatch (e.g. Python code with C++ selected) is stopped with `⚠ Language Mismatch: …` in the sandbox panel and nothing runs. |
| 💀 **Click a 3D seal** | Opens an X-Ray HUD with engine, stage time in ms, severity breakdown, and status. |
| 🖱️ **Drag the graph** | Orbits the ritual altar; page scroll stays intact. |
| 🔍 **SPECTRAL DIFF** | Shows the original vs purified artifact line-by-line with `-` / `+` highlights. |
| 🧪 **TEST SANDBOX** | Runs JavaScript in a local Blob Web Worker (2-second timeout) or sends any other runtime to the remote Paiza.IO proxy (25-second client deadline); stdout, stderr, build errors, and exit code are shown. |
| 🕰️ **HISTORY** | Opens the last-10 run drawer; one click restores code, directive, findings, fixes, engine, summary, and logs. |
| 📋 **Copy / Download** | Retrieves the full purified artifact from `finalCode`. |
| 🧾 **EXPORT REPORT** | Downloads `necrocode-exorcism-report.md` with the full autopsy, including the health score. |
| 🩹 **.PATCH** | Downloads `necrocode-fix.patch`, a unified diff for the artifact's path. Run `git apply necrocode-fix.patch` at the repo root to apply the fix. |
| 🛡️ **Health badge** | The terminal header shows the Code Health & Security Score before → after, e.g. `46 → 100 /100`. Score = 100 − 15 per critical − 6 per warning − 2 per info (JS/TS/TSX only). |
| 🎛️ **FX & Audio** | Header popover with four switches: **Horror BGM** (looped `/audio/horror-bgm.mp3`, on by default, `0.22` idle / `0.85` surge), **3D Audio FX** (synthesized SFX incl. the `DHUM!` slam, off by default), **CRT** (scanlines), and **Fog** (drifting fog + rune grid). |
| 📑 **Grimoire tabs** | The right panel has **Logs**, **Spectral Diff**, and **Sandbox** tabs under a fixed toolbar (**Gen test**, **Test sandbox**, **Copy**, **Report**, **.patch**). Running a test switches to **Sandbox**. |
| 📱 **Mobile** | Below 1024px, a **Spellbook / 3D Ritual / Grimoire** switcher shows one panel at a time. |

keys remain in each visitor's browser and are never stored as Vercel env vars.

provider attempt has an 8-second timeout before fallback.
